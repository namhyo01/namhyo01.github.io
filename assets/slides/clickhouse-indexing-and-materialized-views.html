PART 3 · MV의 정체

저장된 SELECT가 아니라 INSERT에 붙은 트리거

다른 DB의 MVClickHouse MV
언제주기적으로 재계산소스에 INSERT가 들어올 때마다
입력소스 전체방금 들어온 블록만
과거 데이터반영❌ MV 생성 이전 데이터는 자동 반영 안 됨
GROUP BY전체 기준⚠️ 블록 안에서만 → 같은 키의 부분 결과가 여러 행
비용별도 배치⚠️ INSERT 지연에 그대로 더해짐
그래서 타깃 엔진(Summing / Aggregating)이 Merge 때 부분 결과를 다시 합쳐야 한다.

PART 4 · 집계 상태

더할 수 없는 값은 상태로 저장한다

MV에서 저장타깃 컬럼 타입다음 단계 (연쇄)최종 조회
uniqExactState(user_id)AggregateFunction(uniqExact, UInt64)uniqExactMergeStateuniqExactMerge

AggregatingMergeTree는 AggregateFunction / SimpleAggregateFunction 컬럼만 합치고, 일반 컬럼은 한 행 값만 남긴다. 개발 중엔 Merge가 늦어 안 보이고, 운영에서 대시보드 숫자가 줄어든다.

PART 4 · 🔬 실측 · 연쇄 MV

1분 테이블에 직접 백필하면 1시간 테이블은?

CREATE TABLE l1 (h DateTime, c UInt64)
  ENGINE = SummingMergeTree ORDER BY h;
CREATE TABLE l2 (d Date, c UInt64)
  ENGINE = SummingMergeTree ORDER BY d;
CREATE MATERIALIZED VIEW mv_l2 TO l2 AS
SELECT toDate(h) AS d, sum(c) AS c
FROM l1 GROUP BY d;

-- MV를 거치지 않은 '직접 백필'
INSERT INTO l1 VALUES ('2024-01-01 01:00:00', 7);
SELECT sum(c) FROM l2;
l2 결과
7자동 전파됨
연쇄 MV는 중간 테이블에 들어오는 모든 INSERT에 반응한다 (Merge에는 반응 안 함). 하류 테이블을 따로 또 백필하면 두 번 들어간다. 체인은 2~3단계 이내 (저자 권장).

PART 4 · 🔬 실측 · 백필

POPULATE는 25.8에서 교재대로 안 된다

CREATE MATERIALIZED VIEW mv_pop TO tgt POPULATE
AS SELECT …;
-- ❌ Code 62: you can't declare both
--    'TO [db].[table]' and 'POPULATE'

SELECT 1 SETTINGS
  materialized_views_populate_atomically = 1;
-- ❌ Code 115: neither a builtin setting …
무중단 백필 순서
1빈 타깃 테이블 생성
2신규 INSERT용 MV 생성
3MV 이전 구간만 월 · 일 단위로 타깃에 직접 INSERT … SELECT
4경계 구간 중복 · 누락 검증
교재가 언급한 설정은 25.8에 없다 (26.x 기능일 수 있음). 결론은 교재와 같다: 운영 백필은 수동 INSERT … SELECT.

PART 4 · 🔬 실측 · ATTACH PARTITION

'O(1) 무중단 교체'라는데 정말 교체될까?

CREATE TABLE a (d Date, v UInt64) ENGINE = MergeTree
  PARTITION BY toYYYYMM(d) ORDER BY d;
CREATE TABLE b AS a;
INSERT INTO a VALUES ('2024-01-05', 1);
INSERT INTO b VALUES ('2024-01-05', 100);

ALTER TABLE a ATTACH PARTITION '202401' FROM b;

ALTER TABLE a REPLACE PARTITION 202401 FROM b;
명령 후a의 값
ATTACH⚠️ [100, 1] — 추가됨
REPLACE✅ [100] — 교체됨
ATTACH PARTITION … FROM은 하드링크 복사 · 추가. 타깃에 같은 파티션이 있으면 중복. 교체가 목적이면 REPLACE PARTITION.

PART 4 · 🔬 실측 · MV 안의 JOIN

오른쪽 테이블이 바뀌면 집계도 바뀔까?

CREATE MATERIALIZED VIEW mv_j TO seg_cnt AS
SELECT u.seg AS seg, count() AS c
FROM ev AS e JOIN users AS u
  ON e.user_id = u.user_id
GROUP BY seg;

INSERT INTO users VALUES (1, 'gold');
INSERT INTO ev VALUES (1);
INSERT INTO users VALUES (2, 'silver');
INSERT INTO ev VALUES (3);   -- users에 없음
seg_cnt
('gold', 1)끝
MV는 FROM의 가장 왼쪽 테이블(ev) INSERT에만 반응한다. users 변경은 무시, 과거 결과도 재계산 안 됨. INNER JOIN이라 아직 없는 사용자의 이벤트는 조용히 사라진다.
